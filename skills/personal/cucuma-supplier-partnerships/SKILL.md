# Cucuma Supplier Partnerships

Own supply relationships and their handoffs. Use small modules; do not run the entire onboarding workflow for a single requested output. Customer sales belong to `cucuma-sales-crm`; product normalization to `cucuma-catalog-merchandiser`; legal interpretation to `cucuma-compliance-risk`.

Read the [composition contract](../cucuma-chief-of-staff/references/composition.md), then only the matching module:

| Request | Module |
|---|---|
| Extract a website, brochure, image, name card or supplier identity | [source-intake](references/source-intake.md) |
| Assess fit, coverage and whether to pursue | [qualification](references/qualification.md) |
| Tailored pitch, objections, replies or follow-ups | [pitch-and-conversation](references/pitch-and-conversation.md) |
| Compare proposals, negotiate within limits, capture rates and responsibilities | [commercial-terms](references/commercial-terms.md) |
| Renewal, performance, fulfilment/settlement handoffs or partner exit | [partner-lifecycle](references/partner-lifecycle.md) |
| End-to-end onboarding or a partial workflow | [recipes](references/partner-autopilot.md) |

Accept caller-supplied artifacts and start at the requested module. Return its named outputs, evidence, status and next owner. Do not ask the founder to copy data between roles.

Design requests produce instructions only. Prepare requests produce artifacts only. Execution preserves already supplied authorization and verifies actual effects; installing or composing skills grants no messaging, signing, spending, publication or scheduling authority. A negotiated draft is not a signed contract, and a readiness recommendation does not complete an operational onboarding request.

Read [company context](../cucuma-chief-of-staff/references/company-context.md) only when current company facts or commercial claims matter, and verify changeable claims before use.
